# 在线图标库

桌面按 Android 包名直接查找 PNG：

```text
icons/drawable/<packageName>.png
```

例如：

```text
icons/drawable/com.tencent.mm.png
icons/drawable/com.tencent.wework.png
```

## 图片要求

- PNG，建议 256×256 或 512×512。
- 必须保留透明背景；不要把截图背景、网格或白底一起放入图片。
- 单个文件不超过 512 KiB，边长 48–1024 px。
- 主图标文件名必须使用应用的真实包名，区分大小写。

## 加载顺序

1. Gitee 下载镜像仓库 `Smartisan-original-launcher-download` 的 `master` 分支。
2. GitHub `main` 分支镜像。
3. 两个镜像都失败时使用应用原图。

成功下载后写入桌面本地持久缓存 `filesDir/online_icon_cache_v4`。只有两个镜像都明确返回 404 时才写入短期 miss 缓存；网络超时、DNS/TLS 错误等临时失败不会污染不存在记录，后续加载可以继续重试。
更新同名图片后，如需立即让已下载用户刷新，应递增代码中的缓存目录版本，
本轮从 `online_icon_cache_v3` 改为 `online_icon_cache_v4`，下载、预览和备份恢复的源码缓存使用同一版本。
发布新 APK 前应先同步 GitHub／Gitee 图片库，否则新缓存仍可能下载到镜像中的旧图片；图片库不打包进主 APK。

## 应用图标选择

应用图标页的单应用“替换图标”会读取 APK 内：

```text
launcher/assets/icons/variants.json
```

仓库源文件为：

```text
icons/variants.json
```

`variants.json` 用于把一个包名映射到多个候选 PNG。候选文件仍放在 `icons/drawable/`，文件名可以是包名本身，也可以使用语义化类别名或兼容旧库的 `_2`、`_3` 后缀，例如：

```json
{
  "variants": {
    "com.example.app": [
      "com.example.app.png",
      "com.example.app_2.png"
    ]
  }
}
```

单应用选择页会合并系统应用别名、这里登记的变体、当前图标包命中图标、系统原图和相册自定义入口；顶部显示该应用当前实际生效的图标。当前正在使用的候选图标会显示维护版资源中的选中标记。选择“默认图标”会清除单应用替换并回到应用原图。

图标包通过标准 `appfilter.xml` 的 `component` / `drawable` 映射参与候选项；已安装且能命中当前应用的第三方图标包会显示在这里，无需把图标包图片再下载到在线图标库。

`index.json` 是完整文件清单，保留 `_2`、`_3` 等真实候选图，以便同步和完整性校验；单应用变体继续兼容 `variants.json`，应用身份、明确包名／组件别名及全库搜索元数据由 `catalog.json` 补充。不要仅凭后缀判断文件错误，更不能批量删除或改名。

## 系统应用自适应

不同厂商的系统应用包名并不统一。Launcher 会先确认目标是系统应用或更新后的系统应用，再按包名、Activity 名称和系统应用标签识别相机、相册、浏览器、联系人、短信、邮件、计算器、文件管理、指南针、录音、音乐、视频、天气、便签、设置、安装器和 SIM 工具包，并映射到本目录中的锤子标准图标。第三方同名应用不会套用该映射。

系统视频统一请求 `com.smartisanos.videoplayerproject.png`，因此 OPPO、ColorOS、OnePlus 等系统视频应用不再依赖各自包名。`com.android.VideoPlayer.png` 保留为同一类别的可选图标，用户可在“替换图标”中手动选择。

`icons/system/archive/` 仅保存曾被错误归到系统设置候选的历史图片，不参与在线下载、自动匹配或候选图展示。

日历和时钟继续使用 Launcher 已有的动态日期 / 指针实现，不会被静态在线图片覆盖。

新增或替换图片后执行：

```powershell
python tools/generate_icon_index.py
```


## 全库搜索与图标包目录

`catalog.json` 保存名称、包名、明确别名、分类和 sourceId；`search-index.json` 及 APK 内同名 assets 是派生索引。自动匹配只用明确身份，全库搜索可匹配名称、关键词、分类及包名。现有 PNG 和 sourceId 不重命名；尚未补充名称／分类的旧条目保留兼容名称并归入“其他”。

构建顺序为源数据审计 → 生成 → 结果审计，见 `docs/build/BUILD_GUIDE.md`。删除 PNG 需要显式清理源引用，生成器不会自动吞掉错误。

“替换图标”的“搜索更多图标”仍在同一个设置宿主内，搜索框复用应用图标页原版资源与宽度，入口／分类行复用该页18sp标签。点击分类打开带原设置转场的下一页，标题显示分类名；返回先回到分类首页并恢复列表位置，再返回替换图标。结果标题右侧显示“共 N 个”，统计当前筛选的在线来源与图标包具体图案条目。

进入页面时在后台准备在线元数据和已安装图标包目录，加载状态仅显示动画；完成前禁用搜索／分类，返回仍有效。首次后台加载还会复用已安装应用的真实显示名与声明类别，并为中文名加入全拼／首字母检索；按键输入不读取PackageManager。已登记的中文名及别名同样拥有拼音关键词；未安装、尚无中文登记的旧图标仍只能靠现有名称／包名／关键词检索。图标包目录复用既有 appfilter 解析，并读取其声明的 drawable / icon_pack 选择目录；不盲扫全部 Android 资源。没有声明的内部图像不会列入。

缓存分别保存元数据和图片：图标包目录持久化到 `cacheDir/icon_pack_search_v1.db`（数据库64MiB上限），按包更新时间与在线目录版本复用，包安装／更新／卸载时失效。系统清理 cache 后可重建。结果元数据分页缓存为4页、每页最多60条；图片仍由 `IconPreviewRepository` 的6–16MiB有界内存缓存按可见 Cell 加载，在线 RAW 保留原 `online_icon_cache_v4` 的64MiB上限。两个有界网络线程与两个预览线程隔离，输入只筛字符串，不下载或解析 appfilter；退出取消本页任务。

允许跨应用选图。在线选择保存 `resource:<sourceId>`；图标包具体图案保存 `pack:<package>#<drawable>`，仍以当前目标应用包名／组件作为数据库 key。旧 `pack:<package>` 配置继续按原规则匹配目标应用，不迁移数据库主键。图标包卸载或图案失效时保留既有回退链；提交前会重新确认具体图案可读取。


## 2026-10-08 分类与检索边界

现有5199张PNG对应4720个应用条目、4625个包名。图标库复用原版 `launcher/assets/apps_category.json` 的精确包名分类，增加新闻资讯、生活实用、交通出行、商务办公、学习教育、金融理财、铃声壁纸、儿童母婴和书刊阅读。尚有2621个应用条目归入“其他”，因为缺乏可靠身份或类别；中文名称和拼音搜索覆盖已审核名称，以及用户手机上实际安装应用的标签，未知包名仍可用包名搜索。图标预览在甩动中继续请求可见图案，并仅预取邻行的本地资源；选中标记与实际来源共用决策。真机流畅度和跨ROM显示以当日开发日志的实测边界为准。

## 2026-10-05 历史验证边界

库文件／应用记录／包名分别为5199／4720／4625；人工名称与分类尚未全量补齐，源catalog仍有4470条归入“其他”。本机已安装应用的真实标签可在后台补充检索，未安装且未标注中文的条目不能保证中文名称可搜到。类别数量及中文检索不足来自元数据，不由Gitee是否推送决定；新PNG是否可下载仍取决于镜像同步。

本机已检查分类下一页／原设置转场、标题与系统返回、共享搜索宽度及结果计数。Android目录检查包括已安装应用标签、中文字符串匹配、可取消查询及0／1／5／20合成包；不等于20个真实包的完整UI验收。真实跨应用选图持久化、备份恢复、进程重启、长期滚动和跨ROM仍待补足，不保证全库准确中文／分类或全项目不卡。用户已要求停止代码处理，最新状态及锁屏／解锁的未完成项见DEVELOPMENT_LOG当日首条；本轮图标搜索验证不能替代解锁流畅度验收。
