# Launcher 修复与优化计划

更新日期：2026-11-07。当前开发版本 **1.6.0-T / 34（测试版）**，正式发布另行安排。

## 文档职责

本页只维护剩余任务、执行顺序和验收条件。根因、修复与实际证据统一见[开发日志](DEVELOPMENT_LOG.md)；旧方案见[历史归档](archive/DEVELOPMENT_HISTORY.md)。当前状态以最新日志和目标设备证据为准，不用历史流水重新生成待办。

## 执行规则：不重复测试

- 已通过且相关实现未变的范围冻结；只在相关代码变化、新故障或新增目标设备时补相应回归。
- 无收益候选停止，不更名重测；未关闭的问题不自动等于需要重新跑全套。
- 每项先列已有证据、尚缺证据和本批具体假设。没有新假设或新证据时不构建诊断包、不重复采样。
- 确认代码缺陷后才最小修复，修前负控、修后专项及必要相邻回归成批执行；性能修改仍需同条件五样本准入。
- 缺少故障机时不循环测试替代机；受控通过与现场验收分开记录，不用测试数量计算完成百分比。
- 不缩页数、不关闭百叶窗、不提前结束Loading，不靠改变原版视觉掩盖问题。

## D．冻结，不作为剩余施工任务

- 1.6.0-T版本标识、作者整行跳转、桌面自身卸载保护、已验证搜索入口、已通过SAF路线。
- 应用自行隐藏／更换入口的组件同步修复：Aurora失效入口和独立别名切换已有证据；完整启动矩阵未全验，但不因缺矩阵重做已通过组件刷新测试。
- Android9返回重新加载：用户确认与后台内存压力相关，清理后恢复；没有新异常不重开A22。
- 最终纹理磁盘缓存、准备任务前移再join、无条件延后页面、无收益常驻截图缓冲及上述无收益微优化不恢复。
