# Smartisan Icon × Smartisan Launcher 当前实施方案

更新于 2026-11-13。本页是两个仓库共同使用的实施入口。部署目标、产品入口和验收顺序以本页为准。V1.0 总规范继续定义其余跨项目合同；现有 API 和 Intent 字段以各自的 v1 协议为准，本文新增的联动能力是待实施方案。

接手工作先看[执行计划与交接记录](ECOSYSTEM_EXECUTION_HANDOFF.md)，其中记录当前云端进度、分步操作和验收条件。

## 要实现的产品

- **图标软件**负责浏览图标、查看本机应用的适配情况、求图、投稿和查看进度。启动默认显示「已适配」的本机应用，首页切换「已适配」「未适配」，右上角「图标库」进入可搜索的图库。「全部图标」是图库范围，使用无名称的图标网格，保留无障碍名称。底部为「应用」「排行榜」「我的」，排行榜内区分未适配排行和贡献榜。未登录时隐藏个人投稿、求图记录等账号专属入口。
- **视觉与交互**沿用 Smartisan 风格，统一标题栏、返回控件、底栏和选中状态，切换动效短且可中断。图标保留原始透明边缘，界面不加棋盘格或外框。普通详情只展示大图、基础信息及作者信息，无下载按钮。由桌面发起的选图允许确认选用，并把结果返回桌面。
- **锤子桌面**负责实际应用图标和原版桌面体验，在线搜索和分类由 Smartisan Icon 提供。联网同步后，两个客户端对同一个组件、包名和发布版本给出一致的适配判断。用户手动选图和本机自定义图标保留原有优先级与持久化语义。

## 服务与数据归属

| 部分 | 职责 |
|---|---|
| 阿里云轻量应用服务器 | 账号与邮件注册、求图和排行、私有投稿原图与历史、技术检查、人工审核、发布任务、PostgreSQL、权威公开目录与备份 |
| Gitee | 保留现有公开 PNG。新发布资源能否继续走 Gitee，由隔离分支的新增、更新、下架和恢复验收决定 |
| Smartisan Icon | 校验并同步正式目录，执行匹配，负责公开 PNG 缓存和按需取图 |
| Launcher | 消费 IconHub 已校验的匹配结果和公开图稿，管理本机图标来源与渲染派生缓存 |

阿里云是新的服务部署目标，NAS 相关记录作为历史证据。服务端写入凭据仅存于部署环境。Gitee 当前 `master` 是既有桌面的图片入口，隔离分支的通过结果还需验证正式读取路径。阿里云提供权威目录，即使 Gitee 目录镜像不可用，也能让双端核对同一版本。若隔离验收确认 Gitee 无法满足 PNG 发布、更新或下架同步要求，使用阿里云作为完整资源源，并先验证桌面迁移与回退。

目录沿用 `release.json`、四份元数据及其 SHA-256、既有 `sourceId` 和图片路径。精确组件映射优先，其次是明确包名和候选变体。搜索结果、待审核记录、本机自定义及临时网络故障均不能改变全局适配状态。冷启动使用本地快照，后台验证整版数据后再原子切换。无有效快照时显示待同步。

## 独立使用与双端联动

本文的联动分工覆盖总规范第六节与旧交接记录中关于 Launcher 独立同步在线目录、下载原始 PNG 和内置在线搜索的实施步骤。发布快照、资源身份、适配规则及 Launcher 原版行为继续遵循总规范。

| 安装状态 | 用户可用功能 |
|---|---|
| 仅 Launcher | 正常设为默认桌面，使用原版图标、动态日历和时钟、第三方图标包、从相册选图及本机备份恢复。开启「改进版图标」时提示安装 Smartisan Icon，保留关闭状态。 |
| 仅 Smartisan Icon | 独立查看本机应用、适配状态、图库、搜索、分类和排行榜。登录后可以投稿、申请适配和查看进度。 |
| 两端均安装且兼容 | 开启「改进版图标」即可使用公开图标。Launcher 的在线搜索和分类由 IconHub 提供。分享与求图由 IconHub 检查登录。 |
| IconHub 已安装但版本过旧 | 联动入口提示升级。Launcher 使用现有本机来源。 |
| IconHub 被卸载、停用或清除数据 | 卸载或停用时改进版开关回到关闭，原有在线选择记录保留并暂时回退。清数据时保持开关偏好并进入待同步。重装后用户可再次开启，已保存的资源按当前目录重新解析。 |

### 强迫症选项中的「桌面联网」

- 新增「桌面联网」开关，首次安装、旧版升级或恢复缺少该设置的备份时默认关闭。关闭时 Launcher 的直接网络请求停用，正在进行的请求取消，排队任务在执行前重新检查开关。用户主动打开需要联网的桌面功能时，提示可在「强迫症选项」中开启。
- 「桌面联网」与「改进版图标」分别控制。桌面联网关闭时，Launcher 仍可通过本机跨应用接口读取 Smartisan Icon 已匹配的结果和已缓存的 PNG，收到缓存更新后局部刷新。Smartisan Icon 使用自己的网络和同步设置，选图、投稿和求图在 Smartisan Icon 中完成。
- 改进版联动路径始终由 IconHub 负责目录同步和下载。Launcher 开启联网后，可使用其自身需要网络的功能，例如检查更新。实现前盘点旧在线图库、天气、更新及其他应用内网络入口，覆盖后台任务、恢复流程和库发起的请求。
- 开关控制 Launcher 自身的请求行为。Android 的 INTERNET 权限由 Manifest 声明，系统级联网限制由设备设置管理。
- 验收覆盖首次安装、旧版覆盖升级、缺少该设置的备份恢复、关闭后取消在途任务、重新开启及重启。桌面联网关闭时，按 Launcher 与 IconHub 的应用身份分别检查网络活动，并验证 IconHub 上架、换图和下架同步后，桌面仍可通过本机接口刷新对应图标及当前主题下的感知阴影。

### 图标匹配、缓存和刷新

- 正式发布的 Catalog Snapshot 是唯一的适配依据。IconHub 复用现有目录与图片仓库，对 Launcher 提供的包名和组件按精确组件、明确包名、有效候选的顺序批量解析。查询按同一个 revision 返回，保留现有系统应用别名、电话／联系人组件分流和 Launcher 的图标优先级。联调需用同一输入核对两边结果。
- IconHub 通过版本化只读接口返回 revision、匹配结果、候选的 sourceId、发布摘要及图稿是否已缓存。Launcher 在后台查询和读取已就绪的 PNG，缺图时由 IconHub 合并请求并按需下载。传图使用受限的内容 URI 或文件描述符。接口限制批量大小和调用权限，按 Android 调用者身份验证对端，正式与测试包分别验证，访问范围仅限已发布图稿。调用方不能指定任意文件路径。
- Launcher 保留现有桌面位图、纹理及必要的有界渲染缓存，供冷启动和滚动读取。IconHub 持有在线目录和原始 PNG 缓存。Launcher 的渲染派生物按 sourceId 和发布摘要关联，保存时原子替换。HOME 首帧、翻页、文件夹和 GL 线程均只使用本地已就绪结果；IconHub 进程冷启、IPC 或网络失败时先显示可用图标。
- IconHub 在有效快照切换或缓存就绪后发出变更通知。Launcher 在后台合并通知，也在启动或回到前台时核对 revision，覆盖后台通知遗漏。相同摘要复用现有派生图，同源换图、匹配变化和撤销只刷新受影响条目。收到正式撤销后停止使用旧图稿，回退到有效候选或原图，保留用户选过的 sourceId；恢复发布后按有效目录重新解析。
- 有有效快照但缺 PNG 时保持匹配状态，桌面临时显示原图并按需取图。无有效快照显示待同步。断网、镜像异常、摘要校验失败和对端进程暂不可用时保留上次已验证结果。包移除或停用属于明确不可用，走安装状态表中的回退。适配状态、缓存就绪和桌面显示来源分别判断。

### 替换图标页与账号

| 操作 | 联动行为 |
|---|---|
| 搜索更多图标 | 用现有 PICK_ICON 传目标包名和组件。IconHub 打开可搜索、分类的图库，返回 resource:<sourceId>。Launcher 重新校验资源和目标后调用 RedirectIconDB 保存，取消或结果无效时保持当前图标。 |
| 从相册选择 | 继续用 Launcher 的本机流程，支持独立使用。 |
| 共享此图标 | 在相册入口下新增。Launcher 传当前实际所选图稿的源 PNG、包名、组件和应用名。自定义来源优先取本机保存的原始素材。公开库来源可传 sourceId，由 IconHub 解析对应正式原图。只有存在可导出源图时才能继续，避免把桌面截图、阴影或放大缩略图当作原图。IconHub 预填草稿，用户填写介绍和来源后确认提交审核。 |
| 申请适配此图标 | 紧跟共享入口。打开 IconHub 的「未适配排行」并定位当前应用，显示已有请求或提供申请入口。应用已正式适配时提示当前状态。用户确认后才提交。 |

- Launcher 检查安装状态、对端身份和协议能力。IconHub 检查登录，未登录时提示并进入登录页，成功后续接同一草稿或求图对象。退出、登录取消和进程重建都有明确返回路径，重复 Intent 或重复提交不产生多份草稿或求图。
- 投稿图片仅授权目标应用读取当前文件，IconHub 校验 MIME、内容、尺寸和大小后导入私有草稿，并按草稿生命周期清理临时文件。图库使用无需登录。登录状态、私有草稿和投稿记录由 IconHub 管理。
- 扩展现有 Intent 协议的能力声明、选图、投稿原图与求图字段；缓存读取增加配套接口。先用 launcher_mock 验证版本协商、旧版兼容、拒绝非法数据、取消和登录续接，再接真实 Launcher。字段和错误码在协议文件落定后进入实现。

### 旧版本迁移与回退

- 保留 `resource:<sourceId>`、自定义图、图标包、组件与用户身份以及备份语义。旧改进版偏好只有在兼容 IconHub 可用时恢复；缺失时提示并使用本机来源。旧在线缓存不参与新目录匹配。切换期间保留旧缓存作为版本回退材料，联动验收通过后再评估清理。
- 联动候选先发布兼容的 IconHub，再发布 Launcher 候选。在线联动故障可以停用对应入口并回到本机图标来源。每阶段留存可回退构建、APK 校验值和数据库兼容检查。

### 双端联动验收用例

| 场景 | 通过条件 |
|---|---|
| 单装任一应用 | Launcher 可作为 HOME 并能本地换图；IconHub 独立浏览和登录投稿。Launcher 尝试开启改进版时有明确提示。 |
| 首次装齐、缓存未就绪、双端升级顺序不同 | HOME 正常出现。兼容后可开启，缓存就绪后局部刷新。旧版对端提示升级，重复点击和返回不改变错误的目标。 |
| 选图及投稿 | 对两个有相同包名但不同组件的入口分别选图，确认结果应用到原目标。覆盖取消、返回、重建、未登录、登录成功和取消。投稿预览原图摘要与实际源素材一致，提交后桌面图标选择保持，求图能定位当前应用。 |
| 上架、同源更新、下架和恢复 | 对同一图标记录每次发布 revision、公开 PNG 摘要、IconHub 查询结果及桌面截图。新增可见、同源更换、撤销回退及恢复分别生效。未发布的审核状态不改变适配判断。 |
| 离线、缺图和对端生命周期 | 核对有效离线缓存、首次离线、网络恢复、缓存被逐出、杀进程、停用、清数据、卸载和重装。临时不可用保持已验证状态，明确撤销后不显示旧在线图。 |
| 旧版覆盖升级及备份恢复 | 使用已有原图、在线手选、自定义、图标包和应用分身记录，确认升级及恢复后选择归属准确。无 IconHub 时可用本机来源，装齐后可重新解析保留的在线记录。 |

## 管理员怎样操作

| 操作 | 服务端与 Gitee 动作 | 用户看见的结果 |
|---|---|---|
| 上传与审核 | 私有保存，校验 PNG、尺寸与摘要，再由审核员批准或驳回 | 投稿者查看进度，批准后进入待发布 |
| 新增上架 | 按稳定资源键上传新增 PNG，从公开入口回读校验；生成完整目录并校验后切换正式清单。Gitee 作为目录镜像时同步同版清单 | 图标出现在图库，两个客户端同步后可搜索和匹配 |
| 更新图标 | 保留同一个 `sourceId` 和历史版本，发布变更图片并校验新摘要，再切换目录。明确处理同 URL 缓存与失败恢复 | 两端换成新图，只失效受影响缓存 |
| 下架 | 新快照移除匹配与搜索入口并记录撤销，更新公开清单与对应 Gitee 镜像。发布失败可重试，后台区分已受理和已同步 | 双端联网同步后停止自动匹配并回退到有效候选或原图；离线设备在下次成功同步时生效 |
| 恢复 | 校验历史资源可读并重新发布有效映射和新快照 | 图标重新出现并可匹配 |

普通下架保留版本和审核历史。如果还要求旧 Gitee raw URL 停止提供字节，需要另验证撤除及缓存行为；后台状态变化本身不能证明公开 URL 已失效。发布时只上传新增或变更的 PNG，对未变更资源复用已核验的基线，避免每次全量写入。

## 当前实现与剩余工作

| 部分 | 本地证据与缺口 |
|---|---|
| IconHub 服务端 | 已有上传、审核、发布适配器和版本清单。平台图标下架及恢复目前只改数据库与版本计数，未走正式快照发布；现有 Gitee 发布遍历全量图片，清单撤销字段仍为空。社区作品与平台图标两条入口都要覆盖 |
| IconHub Android | 已有快照校验、最近有效快照及图片读取缓存。线上入口和资源源切换、完整产品流程仍需联调 |
| Launcher | 当前搜索目录从 APK assets 读取，Gitee 图片按需下载，缓存命中优先；因此目前无法保证新映射、同名更新、下架即时同步。扩展现有 `IconLibraryCatalog`、`IconPreviewRepository` 与原匹配、缓存和桌面刷新链路 |
| Gitee / 阿里云 | 最近一次记录中部分 PNG 可读，Gitee 根目录 `index.json`、`variants.json` 返回 451，`release.json` 返回 404。隔离分支真实写入未验收，阿里云部署、SMTP 与双端生产验收尚无完成证据 |

## 实施顺序与放行条件

1. **服务端发布先闭环。**复用现有发布器，接通新增、更新、下架和恢复，检查失败恢复及重试。验证失败时保留有效目录，避免数据库状态、公开资源与目录版本错位。
2. **阿里云隔离部署与 Gitee 选型。**部署 API、数据库、HTTPS、备份及 SMTP。用一枚测试图标跑完整生命周期，记录公开读取结果、SHA-256、目录 revision 和恢复结果。测试分支不可替代正式路径验收。旧资料里的 NAS 部署和完整离线 APK 属于历史阶段。
3. **先完成接口和独立模式。**补齐 IconHub 匹配与缓存接口、选图、投稿和排行路由。用 mock 验证协议，再接 Launcher 开关、后台图标读取和三个联动入口。两边各做一次只安装本应用的干净安装测试，再测双端同装和原 Launcher 覆盖升级。
4. **同一真机端到端验收。**同一包名和组件依次验证新增、同源更新、下架及恢复，核对后台状态、公开文件、两端 revision、图库搜索、桌面图标和缓存行为。另验证断网、摘要错误和 Gitee 451 时保留有效目录，以及注册邮件、登录、排行榜与页面返回。完成后才切换正式入口。

5. **性能与回归放行。**同一台手机、相同布局和相同图标集，比较旧版与候选的 HOME 冷启动首帧、首次翻页、开文件夹、长帧、主线程阻塞、下载次数和内存。记录冷／热缓存、断网与 IconHub 进程冷启；检查动态时钟／日历、图标包、自定义、备份恢复及至少两种 ROM。任何主线程等待 IPC 或网络、图标优先级回归、升级丢记录、撤销后仍显示旧在线图稿均阻断放行。性能提升以实测数据为准。

两仓库保留同名同内容的本文。架构决策维护在这里，字段细节维护在协议里，部署命令维护在部署文档里，阶段结果维护在开发日志及对应报告里。
